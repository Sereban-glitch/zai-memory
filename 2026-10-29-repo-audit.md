## 1. Резюме простым языком

**Что сделано.** Все 18 репозиториев склонированы и прочитаны: README, исходный код, конфиги деплоя, git-состав. По каждому предложено от 1 до 3 улучшений — всего 50, каждое с доказательством (файл и строка) и объяснением, почему это нужно обязательно, а не «хорошо бы». Домыслы вынесены в раздел «Не проверено».

**Главная находка.** В montage-telegram-bot в открытом виде лежит действующий токен Telegram-бота (в двух Python-файлах, как fallback-значение). Плюс там же закоммичена рабочая база SQLite с персональными данными реального пользователя. Это нужно чинить сегодня: отозвать токен через @BotFather и вычистить оба файла из истории git.

**Три системные проблемы.** Первая: публичный IP продакшен-сервера (35.209.212.217 и 34.46.98.209) раскрыт в четырёх разных репозиториях — вместе с путями и сервисами это готовая карта инфраструктуры для атакующего. Вторая: у 10 из 18 репозиториев нет LICENSE — по умолчанию «все права сохранены», то есть показывать код можно, а легально использовать нельзя. Третья: в git закоммичены тяжёлые артефакты — релизные бинарники (13 МБ, продублированы в двух репо), рабочая база данных, логи, Go-бинарник 10,6 МБ.

**Что хорошо.** Уровень кода в среднем высокий: параметризованный SQL, HMAC-верификация initData в info-bot-go и proakt-build-bot, subprocess без shell=True в Python-пайплайнах, systemd с харденингом. Проблемы — в основном по краям: секреты в дефолтах, публичные эндпоинты без авторизации и неточности документации.

## 4. Критические находки — сделать немедленно (P0)

### 4.1. Действующий токен Telegram-бота в публичном репозитории

montage-telegram-bot, файлы services/worker/pull_worker.py:31 и scripts/news/domdara_to_short.py:25:

```python
BOT_TOKEN = os.getenv("TELEGRAM_BOT_TOKEN", "8519…(редактировано, длина 46)")
```

Формат соответствует реальному токену (ID бота 8519049699 + подпись). Токен используется для отправки видео (pull_worker.py:85). Рядом — личный Telegram-ID владельца (domdara_to_short.py:26, pull_worker.py:107) и IP продакшн-GCP-VM (pull_worker.py:30). Любой посетитель GitHub может вызвать любой метод Bot API от имени бота: читать обновления, рассылать сообщения пользователям, подменить webhook. Документация Telegram требует хранить токен в секрете и отзывать при утечке (core.telegram.org/bots/api#authorizing-your-bot).

**Что делать:** 1) @BotFather → /mybots → API Token → Revoke — старый токен перестанет действовать, даже пока лежит в GitHub; 2) убрать дефолт: `BOT_TOKEN = os.environ["TELEGRAM_BOT_TOKEN"]` (fail-fast); 3) вычистить историю git filter-repo и force-push; 4) впредь — pre-commit хук gitleaks.

### 4.2. Персональные данные в закоммиченной базе SQLite

montage-telegram-bot, db/custom.db отслеживается git (65536 байт, рабочая БД — docker-compose.yml:15,17 монтирует её в продакшн-контейнеры). Внутри — схема Prisma с telegramId/username/firstName/photoUrl (prisma/schema.prisma:16-30) и реальные строки: username @humanrightszp, статус YouTube-канала, история событий. Правило .gitignore:55 (`db/*.db`) не действует — файл закоммичен раньше, чем добавлен в ignore. Публикация ПДн подпадает под GDPR (ст. 5/32) при работе с пользователями из ЕС/Украины. **Что делать:** `git rm --cached db/custom.db .env`, вычистить историю, сделать seed с синтетическими данными (заготовка src/lib/seed.ts уже есть), уведомить пользователя.

### 4.3. Публичные IP продакшн-серверов в четырёх репозиториях

- 35.209.212.217 (GCP-VM agrobot-prod): montage-telegram-bot/services/worker/pull_worker.py:30, archi-2026/deploy/config.yaml:14 и :45, Sereban-glitch.github.io/archi-dashboard.js:3 и deploy/Caddyfile:1
- 34.46.98.209 (прод AgroBot): AgroBot-external/docs/tz_addendum_v1.md:21,22,35 + дубли в 7 файлах ревью

### 4.4. Fail-open аутентификация в proakt360-web (внутри zip)

src/db/auth.ts:40 — `if (!isAuthRequired(s.passHash)) return true;` — без установленного пароля верификация проходит всегда, а src/db/http.ts:57-63 открывает все роуты, включая разрушительный backup/restore (src/app/api/backup/restore/route.ts:20). Пароль хешируется одиночным SHA-256 без соли-итераций (auth.ts:14-16, 31-33) — брутфорсится на GPU. README.md:41-42 сам называет это блокером №1. **Что делать:** fail-closed + форсировать установку пароля при первом входе; заменить SHA-256 на scrypt (есть в Node без зависимостей).

### 4.5. Команды без авторизации в agy-claw-bot

Проверка `userId !== ALLOWED_ADMIN_ID` есть только в bot.js:554 (bot.on('message')). Команда /del (bot.js:474-494) доступна любому и выполняет fs.unlinkSync по пути из текста ответа; без защиты также /clear (:508), /model (:514) и callback_query (:535-546). Бот — по сути remote shell (README.md:77), имя бота публично раскрыто в soul.md:3. **Что делать:** первой строкой каждого обработчика — проверка isAdmin; блэк-лист execBash (bot.js:106-111, проверяет только начало строки) заменить на разбор argv с белым списком.
